- [HIGH] (2026-06-11) command-center (Operations Hub) worker.js serves ALL client-side JS inside a backtick template literal in `chatPage()`. Backslash escapes silently corrupt the served HTML and kill the entire `<script>` block (dead buttons, empty sidebar, no JS at all). NEVER use regex literals with `\` escapes — `/\*...\*/g` collapses to `/*...*/g` which JS reads as a block comment, leaving the trailing flag dangling → "g is not defined". NEVER put `\n`/`\t` in single-quoted strings (→ literal newline breaks the parse). NEVER use `\'` (→ bare apostrophe terminates the string). Use `new RegExp('[*]([^*]+)[*]','g')` with character classes (like the existing `renderMd()` does), `String.fromCharCode(96)` for backtick, `&rsquo;` HTML entities, and `' | '`/`String.fromCharCode(10)` for separators. One mangled token kills everything. Chrome "working" while Firefox/mobile broke = stale cache masking the bug; always wrangler deploy + hard refresh (Cmd+Shift+R). Burned 3× in one session.
